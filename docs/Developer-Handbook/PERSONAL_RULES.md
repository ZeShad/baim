# PERSONAL_RULES.md

## Purpose

These are the personal rules for working with this project.
They describe how the AI should collaborate with the project owner.

---

# Teaching First

Always explain before changing code.

Teach concepts instead of only solving problems.

Assume the user wants to understand the project.

Explain WHY, not only WHAT.

---

# Coding Style

Prefer small, safe changes.

Do not rewrite working systems without approval.

Respect AGENTS.md.

Never rename stable IDs without approval.

---

# Communication

Use simple English.

Avoid unnecessary jargon.

Use examples whenever possible.

When introducing a new concept, compare it to something familiar.

---

# Commands

Never give terminal commands without explaining what each command does.

Explain expected output.

Explain possible errors and how to fix them.

---

# Learning

After each coding session provide:

- What we accomplished
- What I learned
- What is still unclear
- Suggested next step

Maintain the Developer Handbook as we learn.

---

# Documentation

Whenever we understand a new system, document it in the Developer Handbook.

Documentation should be written for future-me six months from now.

---

# Decision Making

Pause before major architecture changes.

Explain alternatives before recommending one.

Discuss trade-offs.

---

# Long-Term Goal

Build not only a great game, but also deep understanding of every system used to create it.

# Code Review Request

## Purpose

Review the selected code or changes for correctness, clarity, maintainability, architectural fit, and risk without modifying files unless explicitly approved.

---

## Before Reviewing

1. Confirm what should be reviewed:
   - a file,
   - a group of files,
   - a commit,
   - a branch,
   - or the current Git diff.
2. Read `AGENTS.md`.
3. Read `docs/Developer-Handbook/PERSONAL_RULES.md`.
4. Inspect the surrounding code needed to understand the reviewed changes.
5. Explain the scope of the review.
6. Do not modify files.

---

## Review Priorities

Review for:

1. Bugs and incorrect behavior.
2. Regressions and unintended side effects.
3. Violations of `AGENTS.md`.
4. Architectural problems.
5. Incorrect or unstable IDs.
6. Missing localization.
7. Save-game compatibility risks.
8. Weak error handling.
9. Security or privacy concerns.
10. Missing or insufficient tests.
11. Unnecessary complexity.
12. Unrelated changes.
13. Documentation that is missing or outdated.

---

## How to Report Findings

Order findings by severity:

- Critical
- High
- Medium
- Low
- Suggestion

For every finding:

1. State the file and relevant location.
2. Explain the problem clearly.
3. Explain why it matters.
4. Describe the likely impact.
5. Recommend the smallest safe correction.
6. Separate confirmed problems from optional improvements.

Do not invent issues merely to produce a longer review.

---

## Review Rules

- Prefer correctness over style preferences.
- Do not request refactoring unless it provides a clear benefit.
- Respect the existing architecture and project conventions.
- Do not suggest renaming stable IDs without explicit approval.
- Do not confuse generated files with source files.
- Check whether apparently missing assets are generated by an existing pipeline.
- Mention positive design choices when they are useful for understanding the code.
- Explain unfamiliar technical terms in simple language.
- Do not commit, push, or modify anything.

---

## After the Review

1. Give a brief overall assessment.
2. List findings in severity order.
3. State whether the reviewed work appears safe to merge.
4. List any tests that should be run.
5. Mention anything that could not be verified.
6. Recommend the next logical action.
7. Wait for approval before making any corrections.

# New Feature Request

## Purpose

Implement the requested feature while keeping the project stable, reusable, and easy to understand.

---

## Before Writing Any Code

1. Explain your understanding of the requested feature.
2. Explain how it fits into the existing architecture.
3. List the files that will probably be modified.
4. Explain any possible risks or side effects.
5. Suggest the smallest safe implementation that solves the full request.
6. Wait for approval before making changes.

---

## During Implementation

- Prefer small, focused changes.
- Follow `AGENTS.md`.
- Follow `docs/Developer-Handbook/PERSONAL_RULES.md`.
- Keep systems reusable.
- Avoid unnecessary refactoring.
- Do not rename stable IDs.
- Do not modify unrelated files.
- Explain important design decisions.
- Add or update tests when appropriate.
- Do not commit or push without explicit approval.

---

## After Implementation

1. Summarize what changed.
2. Explain why each file changed.
3. Report which tests were run and whether they passed.
4. Mention anything that could not be tested.
5. Check and report the current Git status.
6. Suggest possible improvements.
7. Recommend the next logical development step.
8. Wait for review before committing or pushing.
